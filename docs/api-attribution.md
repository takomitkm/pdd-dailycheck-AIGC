# 离线归因：把已经存下来的失败帧拿去过一遍外部视觉接口

现役工具：`tools/vlm-attribute.sh`（本地与主机 `/tmp` 上跑的那份字节一致，md5 `cb3a99e5b60f1275b0d667ae65c4f4c8`，310 行）。
**端点留空**：`~/Desktop/pdd-vlm.url` 现在不存在，工具里也没有任何 URL —— 这是当前要的状态（等接口给定），
不是没做完。
**识别质量未测** —— 下面所有"通过"都只证明管线，不证明接口读得准。

## 一句话

失败的那一帧 PNG 交给视觉大模型问「这屏写着什么、写在哪」，和本地六档在同一帧的判定并排打出来，
用来决定 `ALIAS_` / `PILL_` / `REGION_` 怎么改。它是**线索生成器**，不点任何东西。

## 为什么不并进点击链

`pdd.sh` 的定位是 fail-closed 的：读不到字就不点、坐标兜底那一枪 `verify_light` 判失败。
这依赖一个性质 —— **tesseract 读不到时返回空**。VLM 没有这个性质，它会为了答完问题编字：
幻觉出来的「立即点亮」是带着文字和分数回来的，六档闸门看不出差别，于是点向一个不存在的按钮。
所以它只能站在链路外面当线索，不能当点击依据。这条跟选哪个模型无关 ——
tesseract 的识别率再怎么被嫌弃，它的失败模式是"不给"，而 VLM 的失败模式是"给一个看起来对的"。

## 还不做的三件事

- 不并进 `pdd.sh`，不进点击链，不产出 `COORD_*`（上面那条理由）。
- 不改任何配置：只往 `建议配置.txt` 里写建议，抄不抄由人决定；抄完要照旧跑沙箱和负对照，
  并且先拿同一帧验本地档认不认得到（见下面「抄进配置之前」那两件事，工具自己会把这两句打在汇总后面）。
- 不重试、不落凭据、不把 `raw` 往任何地方发。端点留空期间它的用途就是"把要发的东西算给你看"。

## 用法（都在主机上，证据本来就在主机）

```sh
# 1) 把工具推上去
scp tools/vlm-attribute.sh deb-h61:/tmp/

# 2) 先干跑：一字节都不出站，只落请求体、报"要发几帧、每帧多大"
ssh deb-h61 'bash /tmp/vlm-attribute.sh ~/Desktop/pdd-runs/2026-10-30/191958 --key bag --max 3'

# 3) 接好端点再出站（端点文件第 1 行 URL、第 2 行可选 Bearer key）
ssh deb-h61 'umask 077; printf "%s\n%s\n" "<端点>" "<key>" > ~/Desktop/pdd-vlm.url'
ssh deb-h61 'bash /tmp/vlm-attribute.sh ~/Desktop/pdd-runs/2026-10-30/191958 --key bag --max 3 --send'
```

参数：`--key <key>`（同时把选帧收到 `*-<key>-*.png`，否则它只改标签、会拿别的屏的框出建议）、
`--glob <模式>`（显式覆盖选帧）、`--max N`、`--send`、`--no-local`、`--out DIR`。
目录给到 `<日期>` 或 `<日期>/<时分秒>` 都行，帧的 key 默认取自文件名 `秒-key-轮.png`。

## 端点和 key 按凭据处理

- 只从 `VLM_API_URL_FILE`（默认 `~/Desktop/pdd-vlm.url`，权限 600）读；环境变量 `VLM_API_URL` /
  `VLM_API_KEY` 优先。全程只报来源和长度，绝不打印值。
- 请求体 `*.req.json` 里没有 URL 也没有 key（实测见下面 D 项），所以可以直接贴给人看。
- 没有端点又要 `--send` = 退出码 78，且在**建任何请求体之前**就退（实测 `*.req.json` 数 0）。
- `githooks/patterns.sh` 那份正则表认的是 ServerChan / 私钥 / GitHub PAT / Slack / AKIA 五类**形态**，
  通用 API key 不在里面 —— 门禁挡不住它，所以「值不进仓库」这条只能靠人：别把端点或 key 写进
  脚本、文档、提交信息。另外 `report.txt` 里是接口读回来的屏上文字（可能含昵称、券面额这类），
  `<帧>.raw` 更是接口的原始响应 —— 这两个别往公开地方贴；要贴就贴 `*.req.json`，里面只有图和提示词。

## 输出目录里有什么

| 文件 | 是什么 |
| --- | --- |
| `report.txt` | 逐帧并排：`本地 <replay 那一行>` + `接口读回 N 行`（文本、框、是否命中 `ALIAS_<key>`） |
| `建议配置.txt` | 只写 `PILL_<key>=x0,y0,x1,y1` 和一句 `# REGION_<key> 得把这个框包进去`。**永不写 `COORD_*`** |
| `候选词.txt` | 每个「有框且在 0..1」的接口行一行：`key \t 框 \t 原文本`，用来跨帧找反复出现的词 |
| `本地replay.txt` | `pdd.sh replay <运行目录> --ocr` 的原文，`report.txt` 里「本地」那一栏就从前挑 |
| `<帧>.req.json` / `<帧>.raw` | 请求体和接口原始响应；前者可外贴，后者**带着屏上内容，别贴** |

汇总行那两个数的口径：`接口带框的行` = `候选词.txt` 的行数（在 0..1 内才算有框），
`能对上现有词表` = `建议配置.txt` 里 `^PILL_` 的行数。后者 ≤ 前者。

## 读数之前要知道的口径

1. **默认一个字节都不出站**。截图里带着账号昵称和券面额，`--send` 是你当场做的决定，工具不替你决定。
2. **`band-*` / `pill-*` 裁片默认排除**：那是同一屏的局部放大，发出去等于把同一帧问两遍，
   而且接口会读到半截字，报回来的框也对不上整屏。
3. **框不在 0..1 就不采纳**，且会把原值打出来（不少接口返像素或千分度）。照抄那种数进 `PILL_`
   会把点击点到场外，所以这里直接判「不是比例，别抄进配置」。
4. `命中 ALIAS_` 只说明接口读到的那行和现有词表对得上，**不等于该点它** —— 兑换、领受那一类
   永远只喊人点，配不上 `COORD_`，也不该因为接口读到就自动加进词表。
5. 本地那一栏要不要跑，按**运行目录的 png 张数**决定（≤12 张才跑）：一次 `replay` 扫的是整个目录，
   `--max` 限不住它。11-01 00:0x 这台机实测：整页 psm 6 单帧三次 1415 / 1384 / 1461 ms（`192217-bag-1`）、
   2382 / 2274 / 2272 ms（`192010-popup-1`）、3229 / 3381 / 3261 ms（`202944-bag-1`）—— 帧上字越多越慢；
   band 裁片 psm 7 含 ×3 放大和存盘 408 ms；`replay --ocr` 两帧的一场 20 秒 ⇒ 每帧 20÷2 = **10 秒**，
   86 帧的一场按这速率是 86×10 ≈ 860 秒 ≈ 14 分钟。这就是跳过的原因。
6. `VLM_STUB=<响应文件>` 是不走网络的测试后门，命中了会在帧标题上明写「桩响应：只验管线，
   证明不了识别质量」。它只证明解析、匹配、出站闸门这些管道是通的。

## 换接口形状时要动哪里

请求按 OpenAI 兼容的 `chat/completions` 写：`messages` 里一段 `image_url`（`data:image/png;base64,...`）
加一段 `text`（提示词），响应取 `choices[0].message.content`，`content` 是分段数组也吃得下。
形状不一样时只动两处：
- 发出去那一行 → [`vlm_post`](../tools/vlm-attribute.sh#L143)（URL、头、超时、响应落盘）
- 读回来那一段 → [`resp_text`](../tools/vlm-attribute.sh#L150)（从响应里取出纯文本）

请求体本身的形状在 [`build_req`](../tools/vlm-attribute.sh#L128)（要加 `temperature` 之类就动它），
词表对照在 [`alias_of`](../tools/vlm-attribute.sh#L238)（读现役 `pdd.sh` 里的 `ALIAS_<key>`）。

模型名默认**不发**（没配 `VLM_MODEL` 时请求体里连 `model` 键都没有，实测 D 项三帧都是「无」）；
要发就 `VLM_MODEL=<名>`。超时默认 `VLM_TIMEOUT=90` 秒。

## 默认提示词（`VLM_PROMPT` 可整段覆盖）

> 这是一张手机屏幕截图（拼多多的活动页或首页）。把你能看清的中文文本逐行列出来，每行给两个字段：
> `"text"`：照抄屏幕上那几个字，不要补全、不要纠正错别字、不要换成别的说法；
> `"box"`：这一行在图中的位置，写成 `[x0,y0,x1,y1]`，归一化到 0..1（原点在左上角，x 向右、y 向下，
> 分别除以图片的宽高）。
> 只输出一个 JSON 数组，不要解释、不要 markdown 代码块。看不清的行整行省略 —— 宁可少给几行，
> 也不要为了凑格式猜字。

最后那两句是压幻觉的，但**压住没有、压到什么程度都没测**（见"还没测的"）。
`lines_tsv` 那边配合做了两件兜底：返 markdown 代码块会剥壳，返像素/千分度的框会被打回并写明原因。

## 验收轮：`scripts/selftest-vlm-attribute.sh`（11-01 跑过的一轮）

```sh
scp tools/vlm-attribute.sh scripts/selftest-vlm-attribute.sh deb-h61:/tmp/
ssh deb-h61 'bash /tmp/selftest-vlm-attribute.sh'
```

它跑的是 `/tmp/vlm-attribute.sh`（要换位置就 `S=<路径> bash …`），全程不需要端点 —— H 项要的就是 78。
跑完最后一行报 `跳过项 N`。C 到 K 都依赖现成证据帧，而证据只留 `KEEP_DAYS=7` 天，过期后那些项变成
「跳过」并打印缺哪个目录 —— **别把跳过读成通过**。

| 项 | 命令要点 | 结果 |
| --- | --- | --- |
| A | `bash -n` | 过 |
| C | 干跑 `--no-local --max 3` | 请求体 3 个（780,817 / 780,761 / 780,701 字节，其中图 base64 780,096 / 780,040 / 779,980 字符）；响应 0 个；`.err` 残留 0 |
| D | 逐 `req.json` 解 base64 比 md5 | 3/3 与原 PNG md5 一致；搜 `http://` `https://` `authorization` `bearer`（大小写不敏感）**零命中**；`model` 键 3/3 无；提示词 226 字 |
| E | `VLM_STUB` 桩 + `--key bag` | 选到的是真 bag 帧（`192217-bag-1`、`192217-bag-10`）；每帧 4 行里 2 行进 `候选词.txt`（有框且在 0..1）、1 行无框、1 行越界被打回；`建议配置.txt` 2 行 `PILL_bag`；`pdd.sh` md5 跑前跑后都是 `38a85917…`（现役一字未动） |
| F | `content` 是分段数组 + markdown 代码块 | 剥壳后照样出 1 条 `PILL_bag` |
| G | 响应是 `{"error":{...}}` | 帧下打 `[接口报错] invalid api key`，`建议配置.txt` 0 行 |
| K | 帧名推不出词表（`192517-count-prove-bag` → key `prove`） | 帧标题写明「没有 ALIAS_prove —— 只列接口读到的行，不出建议」，4 行照列 |
| H | 端点为空 + `--send` | `rc=78`，且 `*.req.json` 数 0（挡在建请求体之前） |
| I | 本地那一栏（造一个 2 帧的运行目录真跑 replay） | 帧行填进去了：`202944-bag-1 bag band 111 895 抽 福 袋 [ocr] 3`，`建议配置.txt` 尾注带上同一行；估时打印「按每帧 10 秒估 20 秒」，实测 20 秒 |
| J | 86 帧目录 | 打印「本地六档跳过：…有 86 张 png」，不启动 replay |

这轮验收第一次跑 E 项时就暴露了一个真 bug：桩响应 3 行，报告每帧只打出 1 行，而汇总那行老老实实写
`接口带框的行 6`（3 行 × 2 帧）—— 一边说读到了，一边没显示。查出来是内部字段分隔符原本用制表符，
而 bash 的 `read` 把制表符当 IFS 空白，**连续两个会并成一个**，于是「命中词为空」的行少一个字段、
原文掉进末位，整行被静默丢掉。
现在分隔符换成 `0x1f`（单元分隔符），空字段照样是空字段
——见 [tools/vlm-attribute.sh:91](../tools/vlm-attribute.sh#L91) 和 `lines_tsv` 头上那段。
顺带修掉的两处同类问题：`%-26s` 按字节补宽度（中文整张表错位）改成按显示宽度补；
`grep -c . … || echo 0` 在空文件上会打两个 `0`，把汇总行撑成三行。
三条都是**看报告才发现的**，`bash -n` 一个都抓不到。

## 还没测的

- **负对照**：`scripts/negative-control.sh` 那九条测的是 `pdd.sh` 的分支，`tools/` 下的脚本一条都没有，
  这个新工具也没补。上面 A–J 是验收用例（跑通就算过），不是负对照 —— 它们不会"故意改坏一处看会不会挂"。
- **接口识别质量**：没接真端点，一个字都没测过。哪个接口、每帧多少钱、返回的框准不准，全空。
- **提示词有没有效**：默认那段提示词（226 字，实测 D 项报的长度）要求「逐行 JSON + 归一化框 +
