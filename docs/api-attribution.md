## 一句话

失败的那一帧 PNG 交给视觉大模型问「这屏写着什么、写在哪」，和本地六档在同一帧的判定并排打出来，
用来决定 `ALIAS_` / `PILL_` / `REGION_` 怎么改。它是**线索生成器**，不点任何东西。

## 为什么不并进点击链

`pdd.sh` 的定位是 fail-closed 的：读不到字就不点、坐标兜底那一枪 `verify_light` 判失败。
这依赖一个性质 —— **tesseract 读不到时返回空**。VLM 没有这个性质，它会为了答完问题编字：
幻觉出来的「立即点亮」是带着文字和分数回来的，六档闸门看不出差别，于是点向一个不存在的按钮。
所以它只能站在链路外面当线索，不能当点击依据。这条跟选哪个模型无关 ——
tesseract 的识别率再怎么被嫌弃，它的失败模式是"不给"，而 VLM 的失败模式是"给一个看起来对的"。

## 还不做的三件事

- 不并进 `pdd.sh`，不进点击链，不产出 `COORD_*`（上面那条理由）。
- 不改任何配置：只往 `建议配置.txt` 里写建议，抄不抄由人决定；包括 11-01 那份 `pdd-ocr.conf` 在内，
  工具一个字都不写。抄完要照旧跑沙箱和负对照，
  并且先拿同一帧验本地档认不认得到（见下面「抄进配置之前」那两件事，工具自己会把这两句打在汇总后面）。
- 不重试、不落凭据、不把 `raw` 往任何地方发。不带 `--send` 时它的用途就是"把要发的东西算给你看"。

## 输出目录里有什么

| 文件 | 是什么 |
| --- | --- |
| `report.txt` | 逐帧并排：`本地 <replay 那一行>` + `接口读回 N 行`（文本、框、是否命中 `ALIAS_<key>`） |
| `建议配置.txt` | 只写 `PILL_<key>=x0,y0,x1,y1` 和一句 `# REGION_<key> 得把这个框包进去`。**永不写 `COORD_*`** |
| `候选词.txt` | 每个「有框且在 0..1」的接口行一行：`key \t 框 \t 原文本`，用来跨帧找反复出现的词 |
| `本地replay.txt` | `pdd.sh replay <运行目录> --ocr` 的原文，`report.txt` 里「本地」那一栏就从前挑 |
| `<帧>.req.json` / `<帧>.raw` | 请求体和接口原始响应；前者可外贴，后者**带着屏上内容，别贴** |

汇总行那两个数的口径：`接口带框的行` = `候选词.txt` 的行数（在 0..1 内才算有框），
`能对上现有词表` = `建议配置.txt` 里 `^PILL_` 的行数。后者 ≤ 前者。

## 读数之前要知道的口径

1. **默认一个字节都不出站**。截图里带着账号昵称和券面额，`--send` 是你当场做的决定，工具不替你决定。
2. **`band-*` / `pill-*` 裁片默认排除**：那是同一屏的局部放大，发出去等于把同一帧问两遍，
   而且接口会读到半截字，报回来的框也对不上整屏。
3. **框不在 0..1 就不采纳**，且会把原值打出来（不少接口返像素或千分度）。照抄那种数进 `PILL_`
   会把点击点到场外，所以这里直接判「不是比例，别抄进配置」。
4. `命中 ALIAS_` 只说明接口读到的那行和现有词表对得上，**不等于该点它** —— 兑换、领受那一类
   永远只喊人点，配不上 `COORD_`，也不该因为接口读到就自动加进词表。
5. 本地那一栏要不要跑，按**运行目录的 png 张数**决定（≤ `VLM_LOCAL_MAX_PNG` 张才跑，内建默认和
   现役那份配置都是 12）：一次 `replay` 扫的是整个目录，
   `--max` 限不住它。11-01 00:0x 这台机空闲时实测：整页 psm 6 单帧三次 1415 / 1384 / 1461 ms（`192217-bag-1`）、
   2382 / 2274 / 2272 ms（`192010-popup-1`）、3229 / 3381 / 3261 ms（`202944-bag-1`）—— 帧上字越多越慢；
   band 裁片 psm 7 含 ×3 放大和存盘 408 ms。
   **整场按帧数摊是 4~5 秒一帧**：空闲主机上 32 张那一跑 2 分 11 秒（131÷32 = 4.09 秒/帧）、
   17 张那一跑 1 分 25 秒（85÷17 = 5.0 秒/帧），所以 86 张的一场约 86×5 = 430 秒 ≈ 七分钟。
   工具估时用的就是这个 5 秒（[tools/vlm-attribute.sh:214](../tools/vlm-attribute.sh#L214)）。
   - **公开更正一处**：这里原来写的是"两帧的一场 20 秒 ⇒ 每帧 10 秒、86 帧 ≈ 14 分钟"。那个 20 秒
     是真的，但两帧的样本里**进程启动占了大头**，除出来的每帧分量必然偏高，作废。
     结论没变（86 张那种目录仍然不值得为本地那一栏等），只是从"十五分钟"改成"六七分钟"。
6. `VLM_STUB=<响应文件>` 是不走网络的测试后门，命中了会在帧标题上明写「桩响应：只验管线，
   证明不了识别质量」。它只证明解析、匹配、出站闸门这些管道是通的。

## 换接口形状时要动哪里

请求按 OpenAI 兼容的 `chat/completions` 写：`messages` 里一段 `image_url`（`data:image/png;base64,...`）
加一段 `text`（提示词），响应取 `choices[0].message.content`，`content` 是分段数组也吃得下。
形状不一样时只动两处：
- 发出去那一行 → [`vlm_post`](../tools/vlm-attribute.sh#L244)（URL、头、超时、响应落盘）
- 读回来那一段 → [`resp_text`](../tools/vlm-attribute.sh#L251)（从响应里取出纯文本）

请求体本身的形状在 [`build_req`](../tools/vlm-attribute.sh#L229)（要加 `temperature` 之类就动它），
词表对照在 [`alias_of`](../tools/vlm-attribute.sh#L339)（读 `PDD_SH` 指的那份 `pdd.sh` 里的 `ALIAS_<key>`）。

模型名默认**不发**（没配 `VLM_MODEL` 时请求体里连 `model` 键都没有，实测 D 项三帧都是「无」）；
要发就在配置文件里写 `VLM_MODEL=<名>`，或环境变量给一个。超时同理，`VLM_TIMEOUT` 默认 90 秒。

## 默认提示词（`VLM_PROMPT` 可整段覆盖）

> 这是一张手机屏幕截图（拼多多的活动页或首页）。把你能看清的中文文本逐行列出来，每行给两个字段：
> `"text"`：照抄屏幕上那几个字，不要补全、不要纠正错别字、不要换成别的说法；
> `"box"`：这一行在图中的位置，写成 `[x0,y0,x1,y1]`，归一化到 0..1（原点在左上角，x 向右、y 向下，
> 分别除以图片的宽高）。
> 只输出一个 JSON 数组，不要解释、不要 markdown 代码块。看不清的行整行省略 —— 宁可少给几行，
> 也不要为了凑格式猜字。

最后那两句是压幻觉的，但**压住没有、压到什么程度都没测**（见"还没测的"）。
`lines_tsv` 那边配合做了两件兜底：返 markdown 代码块会剥壳，返像素/千分度的框会被打回并写明原因。

`grep -c . … || echo 0` 在空文件上会打两个 `0`，把汇总行撑成三行。
三条都是**看报告才发现的**，`bash -n` 一个都抓不到。

读数：

1. **工具那个"逐行 JSON + 归一化框"的契约，两个模型七次一次都没遵守过**（A 和 D 的行首 `{` 计数都是 0）。
   两个产出文件因此恒 0 行。这不是鉴权、不是网络、也不是图没送到（请求体里的 base64 按 D 项那套 md5 校验过），
   是**提示词约定和模型自己的输出约定对不上**。
2. **A 组是教科书级幻觉**：1312 个 token 通顺地编了一段前端组件教程，正文里还凭空造了一个外链和
   一句「不允许重复」——屏上两句都没有。这正好是「为什么不并进点击链」那一节说的失败模式现场重现：
   它不是"读不到"，它是"给一个看起来对的"。
3. **B 组同一条提示词换一帧直接返空**（`completion_tokens=0`）。空返回在 tesseract 那边是"闸门不点"，
   在这边是"报表 0 行"，两种都安全，但第三种（A）不安全。
4. **`OCR:` 这个官方任务词是好使的**：C 和 G 读回来的都是满屏真字 —— C 里有「11.11大促」
   「拼多多首页 > 点百亿补贴 > 参与活动」「4天内再点亮1次必得」「限时抽神券 16元 无门槛券」「抽福袋」
   「最高减20元」；G 里有「百亿补贴」「11.11超级加倍补」「抽福袋」「立即查看」「假一赔十」。
   G 那一帧正是 B 组返空的那一帧。**代价是小字和艺术字照样错**：C 首行把状态栏读成「烟 业巳四 1 午10:03 周」，
   G 里「千副竞」「丽芙纯治疗养颜液」这类也是编的。
5. **框始终没有**：`<\|grounding\|>` 走 chat/completions 这条路只出来一个光杆 `<\|det\|>` 就断了（E、F），
   没坐标。所以 `PILL_<key>=x0,y0,x1,y1` 这类建议**现在这条路给不出来**，不是提示词写错，是这个端点
   没把它的检测模式接出来（`<|det|>` 是特殊标记，chat 接口按普通字符串收发，多半在这层就废了 —— 标 B 级推断，
   没验证过端点侧行为）。
6. `PaddleOCR-VL-1.5`（D）在同一帧 prompt token 是 DeepSeek-OCR 的 2.7 倍（1354 ÷ 495 ≈ 2.74），
   返回也是半真半假（「11.11大促」真，后面接一串葡语/西里尔/泰文乱码）。换成它不解决契约问题。

**所以这条线现在的可用产出是"这屏上有哪些字"，不是"字在哪个坐标"。** 要把它变成能落进配置的 `PILL_` 建议，
得先有一个真给框的端点；只是想知道"本地读不到的那个词屏上到底有没有"，`OCR:` 模式已经够用了，
缺的是把工具的解析器从"逐行 JSON"改成"按行取文本"。这一步动的是 `tools/vlm-attribute.sh`，不动 `pdd.sh`。
