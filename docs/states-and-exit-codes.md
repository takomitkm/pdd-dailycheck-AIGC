# 状态、退出码、账本与通知

脚本"算成功"的口径只有一条：**屏幕上那行进度文字里的数字变小了**。点了几下发出去多少
`input tap` 都不算证据。这一节写清楚各种终态各自怎么处理。

## lit：本轮判定出来的终态

`pdd.sh run` 在点「立即点亮」之前先读一遍屏幕（`CHECK_DONE_BEFORE=light`），跑完再核实一次。
产出的 `lit` 记进 `summary.txt`：

| lit | 屏幕上是什么 | 怎么处理 |
| --- | --- | --- |
| 0 | 没走到任何一种终态 | 按失败处理，不写今天标记 |
| 1 | 「已点亮 / 明日再来 / 明天再来 / 已使用」（`ALIAS_done`） | 这一轮没得可点，**算完成**，写标记，退出 0；日志和推送抄屏幕上读到的那几个字，不写成「今天已经点过」（见下面「已使用」那一节） |
| 2 | 「立即兑换 / 去兑换」（`ALIAS_exchange`） | **脚本不代点**，只推送；不写标记（下次还会来看）；退出 0；**不关 app**，停在能直接接手的那一屏 |
| 3 | 进度数字真的变小了 | 正常成功，写标记 |
| 4 | 「点亮任务已完成 … N天后可兑换 / 待兑换」（`ALIAS_pend`） | 7 天周期跑完、奖励在等人工兑换。**不算错误**：只发推送，一个按键都不多放，不关 app |

`NO_CLOSE_LIT="2 4"` 就是最后两种"手机停在拼多多里等她"的来源。其他终态跑干净了会
`force-stop`（`CLOSE_APP_ON_OK=true`）——它留在前台会占住任务栈，下次启动可能被带回旧页面。

## 推送标题：通知栏里那一行字

10-27 起的口径（[pdd.sh:1490](../pdd.sh#L1490) 那一段 `case $lit`）：**标题里不写日期**，日期在正文和
`summary.txt` 里；五种结局各用一个符号分开，扫一眼就知道要不要动手。

| 什么情况 | 标题 | 位置 |
| --- | --- | --- |
| rc=0 且进度数字变小（lit=3） | `PDD ✅` | [pdd.sh:1502](../pdd.sh#L1502) 的默认值 |
| rc=0 且 lit=1、屏幕上读到的字里含「已使用」 | `PDD 已使用` | [pdd.sh:1503](../pdd.sh#L1503) |
| rc=0 且 lit=1、读到的是「已点亮 / 明日再来 / 明天再来」 | `PDD ✅` | 同上，只有含「已使用」那一支改标题 |
| lit=4（整轮到头、等 N 天后兑换） | `PDD 💡` | [pdd.sh:1496](../pdd.sh#L1496) |
| lit=2（屏幕上写着「立即兑换」） | `PDD 需人工` | [pdd.sh:1491](../pdd.sh#L1491) |
| rc=6（点完了但数字没变小） | `PDD ⬛ 退出码 6` | [pdd.sh:1509](../pdd.sh#L1509) |
| 其余 rc，以及开局三道闸（缺 tesseract / 设备掉线 / 锁屏） | `PDD ❌ …` | [pdd.sh:1388](../pdd.sh#L1388)、[:1392](../pdd.sh#L1392)、[:1395](../pdd.sh#L1395)、[:1514](../pdd.sh#L1514) |

两点写在这儿免得日后读代码时误会：

- **标题分档不影响任何判定**。它读的是 `DONE_WORD`（lit=1 那一支从屏幕上抄下来的字），
  lit、标记、点枪数一律照旧。所以「PDD 已使用」和「PDD ✅」在账本上是同一种日子。
- 旧文案里的「需要你动手」换成了「需人工」，这一档**没有 emoji**（她 10-27 点名要的措辞）。
  历史文档里出现的「PDD 需要你动手 10-xx」「PDD 已点亮」「PDD 完成」「PDD 没点亮」「PDD 失败」
  都是 10-26 及之前真发出去过的标题，保留原文不改，用于对老记录。

编码是实测过的：拿现役那条形同一个的 `curl -G --data-urlencode "title=…"` 打本机回环端口，
六个标题服务端解出来的字节和源文件逐字一致（`✅`=e2 9c 85、`❌`=e2 9d 8c、`💡`=f0 9f 92 a1、
`⬛`=e2 ac 9b）。**没有实测的是真推到她手机上那一趟**——那要动她的通知，没打招呼不做。

奖励浮层（`ALIAS_prize='翻倍券|提前锁定'`）只在**进度行读不到**那条路上拿来当成功证据：
10-10 实测它同时挡住进度行和那颗胶囊，于是进度读不到、已点亮也读不到，脚本把成功当失败报了 6。
这段文字本身就是发奖凭据。浮层上的主按钮「开心收下」认到字就点认到的位置，认不到退到
`COORD_take` 那颗量好的中心 `(359,752)`（10-10 那一帧量的，10-11 到 10-20 中午是空的）；
日志会写「按量好的中心收」而不是「认到」，这一枪是盲的、看得出来。

## 「已使用」这一档：券用掉了，不是任务做过了

10-25、10-26 两天各推了一条「PDD 失败 退出码 5」，实际什么都没坏——她那天已经把兑换到的券
买掉了。屏幕上活动页顶部那行进度提示**整行消失**，换成一张「5折 最高减15元 已使用」。
于是三条证据同时为空：进度行没有、`ALIAS_pend`（任务已完成 / N天后可兑换 / 待兑换）一句都不在、
`band` 档又读不出那行小字（默认 psm 7 全空，psm 6 才 12/12，见
[locate-channels.md](locate-channels.md) 第二节），`PROVE_KEY` 拦下来之后三枪各报一次 FAIL，
收工报 5。改两处：`OCR_PSM_BAND_done="7 6"` 让那行字读得到，`proof_ok`（[pdd.sh:1076](../pdd.sh#L1076)）
补第三条救法——进度行和 pend 都读不到时，`REGION_done` 里认到 `ALIAS_done` 任一形状就算
"页面进对了，这一轮没得可点"。

**这一档不给终态结论**，只把"页面进对了"这一层分开：认到「已使用」不等于"今天点过"，
更不等于"券已核销就不用再跑了"。到底算 lit 几，仍然由点「立即点亮」之前的
`CHECK_DONE_BEFORE=light` 判（读到 done 那四种字 → lit=1）。所以日志和推送正文抄屏幕上
读到的字（`DONE_WORD`，[pdd.sh:265](../pdd.sh#L265)），旧文案那句「今天已经点过」在这里是假话——
**公开更正**：10-26 之前的 lit=1 推送不管读到什么都写"已经点过"，而这两种情况意思不一样。
推送正文只压掉 OCR 塞进去的中文字间空格（`5 折 最 高 减 15 元 已 使 用` → `5折最高减15元已使用`），
run.log 留原文；这条压空格纯粹是给眼睛看的，不参与任何判定，所以沙箱不钉它，
它的正确性靠一串字面替换本身。

误报的门留在哪儿：这一条把核实放宽了，前提是 `REGION_done` 那块几何里出现那四个形状之一。
10-26 晚上把七天保留窗口全量扫了一遍：**333 帧命中 7 帧，这 7 帧全是活动页/终态屏，另外 274 帧 0 命中**
（分母 = 492 张 PNG 减 140 张 band/pill 裁片减 19 张 `*-done-*` 帧，`492 − 140 − 19 = 333`；
口径和逐帧表在 [calibration.md](calibration.md) 三）。这一遍是**上界**（整页识别文本都不出现，带闸门必然也不出现），
所以非活动页那一侧现在量到 0 是硬的。真正没被排除的是语义：「已使用」是券的状态、不是"今天点亮过了"，
保留证据里没有一帧同时写着「已使用」和「再点亮 N 次」，可那只是七天窗口的一致性。
哪天一轮进行中券卡就写着已使用，这一枪会把"没点到"报成"这一轮到头"。这条写在 README 已知残留第 9 条。

**这条门 10-27 由她定案：不加约束。** 理由是她给的，不是我推的：就算哪天把它当成"这一轮到头了"，
第二天再跑，屏幕上确实还写着已使用，那就重新记一次完成，账上不亏。所以这里**不**加"必须紧邻
5折/减 X 元那一行"之类的第二道判据，等下一轮真跑出反差再说。

给 `ALIAS_done` 加词的时候只加了实测到的「已使用」，「已兑换 / 已领取 / 已抢完」一个都没加——
那三种形状在这批证据里一次都没出现过。

## 进度行怎么读

`COUNT_TEXT='再点亮|天内点亮'`，在这个词后面找数字。

- 旧措辞「7天内再点亮4次必得」：那个 4 = **还剩 4 次**
- 10-16 起新措辞「9天内点亮6次必得」：没有「再」字。这个 6 到底是"还剩 6 次"还是"总共 6 次"
  **还没测**。核实仍按"变小才成功"，万一它反过来往上加，会报 rc=6 并把两个数字都写进推送
  —— 那就是第一次实测

## 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 成功，含 lit=1/2/3/4 四种终态 |
| 2 | 设备连不上（`ensure_device` 重连 4 次仍失败） |
| 3 | 手机锁屏（`ABORT_IF_LOCKED=true`，有密码时直接放弃，不瞎点） |
| 5 | 卡在某一步没找到（基数 4，每完成一步 +1）。「抽福袋」认不到字会先打 `COORD_bag` 那一枪，点错帧的话由 `PROVE_KEY=bag` 拦下来，最后也是这条。10-25/10-26 连报两天的这条是**假报警**（券用掉了、三条证据全空），现在那条路判 lit=1 退 0，见上面「已使用」那一节 |
| 6 | 点完了但进度数字没变、或者读不到 —— 当失败，**不写今天标记** |
| 7 | 前台不是拼多多 |
| 69 | 找不到 adb，不在 PATH 里（`replay` 不检查这条，它是纯离线的） |
| 78 | 配置缺、比例写错、或没有 tesseract |

每种情况都会推一条通知，正文里带上最后停在哪个 activity。

## 兑换账本：`~/Desktop/pdd-pause`

这个文件里只有一个数字，等于屏幕上那句「N天后可兑换」的 N。**它现在只是账本，
任何数字都不挡路**，每天 10:00 照常碰手机。"收条对不上就跳天"那个闸门 10-11 已经废掉了。

写法三条，都不需要人手抄：

- 读到屏幕上那个 N 就照抄
- 那天读不到 N，就把账上的数减 1（绝不猜，读不到 `PEND_DAYS` 就留空）
- 跑回正常点亮周期写 0；lit=2（屏幕上已经是「立即兑换」）也写 0 —— 倒数已经走完，
  挂着个 1 天读起来像还有得等

真要整天不跑只有一个开关：`systemctl --user stop pdd.timer`。

## 恢复与核实这条路上禁坐标

`RECOVERY_NO_COORD=true`：进度没核实成功之后那串 BACK / 重试（`IN_RECOVERY=1`）只认字，
认不到就当场收手报错。10-11 那次 rc=5 就是这条的由来——连着 BACK 重试到第三枪时用的是
「分数=0 的 COORD_bag」盲点，而屏幕上早就换成新版式了，点的根本不是福袋格子。
正常第一枪不受影响 —— `COORD_bag` 10-20 14:31 删过、15:15 又恢复（README 已知残留第 1 条），
所以主线认不到字仍然会退到那一枪，只有核实/恢复这一段不许。

## 弹窗那条线是停用的

`ALIAS_dialog=''` 让 `dismiss_dialog` 整个停用。原因写在配置区注释里：唯一能认出它的词
「参与活动」同时也是抽福袋之后那一屏的面包屑，09-27 和 10-07 两次都是它对着自己刚点进去的
页面按 BACK，把人退出去，后面点亮只能拿坐标瞎点还报成功。

标签清空的同时也不会单独触发 `COORD_dialog`：在只有坐标的情况下，"没认到弹窗"和
"认到弹窗"是分不开的。key 留着是为了 `pdd.sh find dialog` 还能手动扫一眼。
真正的广告浮层走 `ALIAS_popup='关闭|跳过广告|暂不|以后再说'`。
