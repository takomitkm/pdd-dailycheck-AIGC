# pdd-dailycheck

每天 10:00 用无线 adb（Android Debug Bridge，走 TCP 而非 USB）在真机上跑一遍拼多多的
百亿补贴日常任务，跑完往手机推一条通知。交付物是一个 bash 文件，另有一份可选的调参配置
（两处 OCR 调用共用，见下），不装框架、不起服务进程。

被自动化的链是固定的四步：**百亿补贴入口 → 抽福袋格子 → 立即点亮胶囊 → 滑动浏览 10 秒**，
外加每轮 20 次下滑。成功与否不靠"点没点到"判断，靠屏幕上的字判断（见
[docs/states-and-exit-codes.md](docs/states-and-exit-codes.md)）。

## 子命令

```
pdd.sh run             完整流程；今天已完成过就直接成功退出
pdd.sh run force       忽略"今天已完成"标记，强制再跑一遍
pdd.sh probe           只抓界面：dump + 截图 + 打印可直接粘贴的 COORD_* 比例行
pdd.sh find <key>      解析一个目标但不点
pdd.sh point <x> <y>   裸坐标点一下（这里收的是像素，不是比例）
pdd.sh shot            存一张截图并打印路径
pdd.sh status          设备 / 依赖 / 标记 / 证据目录概览
pdd.sh replay <目录>   拿存下来的证据离线重跑判定，不碰手机
```

退出码：`0` 成功 / `2` 设备连不上 / `3` 手机锁屏 / `4` 卡在入口那一枪（点完还在首页）/
`5` 卡在某一步没找到 / `6` 点完了但进度数字没变或读不到 / `7` 前台不是拼多多 /
`69` 没有 adb / `78` 配置读不动、值不成形、或没有 tesseract。
完整语义和 `lit` 状态见 [docs/states-and-exit-codes.md](docs/states-and-exit-codes.md)。

## 调参走配置文件（11-01 起）

两处 OCR 调用共用一份 `pdd-ocr.conf`：`pdd.sh` 里那六档 tesseract 读 `OCR_*` / `BAND_*` /
`PILL_TH` / `PILL_SCALES` / `PILL_MODE_<key>` / `PEND_PSM`（13 个键），离线归因那个工具读
`VLM_*` / `PDD_SH`（8 个键）。两边各把对方那一批当"认得但不应用"，所以一份文件放两台机器上
共用，改哪一行都不会误伤另一侧。

- 优先级：脚本内建默认 < 这份文件 < 环境变量 <（工具的）命令行参数
- 格式是一行一个 `KEY=VALUE`，`=` 两边不留空格、值不加引号；值里可以写 `~` 或 `$HOME`，装载时展开
- **不 `source` 这份文件**：自己解析一遍，所以名单之外的键、值不成形的键、凭据形状的键都能当场停在 78
  （装载 [pdd.sh:316](pdd.sh#L316)、值校验 [pdd.sh:370](pdd.sh#L370)、两道闸门
  [pdd.sh:397](pdd.sh#L397) / [pdd.sh:401](pdd.sh#L401)）
- 名单是**一个键一个键列出来的**，不是按前缀放的：按前缀（`PILL_*` / `OCR_*` / `VLM_*`）会把标定框
  `PILL_light`、记账变量 `OCR_CONF_STATE`、凭据 `VLM_API_URL` 一起放进来——那几个既不校验又真会被赋值
- 端点 URL 和 key 永远不写进这份文件，这里只写**放端点的那个文件的路径**
  （`VLM_API_URL_FILE=~/Desktop/pdd-vlm.url`）；写了值的话两边都是 78
- 生效的是哪份文件、取了几个键、被环境变量占了几个：`pdd.sh status` 第二行「OCR 配置」直接打出来
  （[pdd.sh:2028](pdd.sh#L2028)），不用猜
- 想不碰手机就把这套装载与校验单独走一遍：`bash pdd.sh __confcheck`（一个不存在的子命令，
  闸门排在分派之前，所以配置有问题它就 78、没问题它打一行用法就 0）。`scripts/deploy.sh`
  装完就是拿这条收尾的

## 坐标一律写屏幕比例，不写像素

`COORD_*`、`SWIPE_X/Y1/Y2`、`BROWSE_X`、`TOP_SWIPE_Y1/Y2` 都是 `0..1` 的屏幕比例，
运行时乘上当前的点空间才变成像素；`REGION_*` 和 `PILL_*` 本来就是比例。
所以换分辨率（改 `wm size`，或换一台机）不用重校，页面布局没变的情况下 OCR/XML 通道也不受影响。

比例给 **5 位小数**：3 位在 1440 宽的屏上有约 0.7px 的系统偏差，5 位折回像素才一个不差。
写成越界值、写成像素、或多一段，脚本启动时直接 `exit 78` 并打印原值（校验在
[pdd.sh:415](pdd.sh#L415)），不会默默点到 `(0,0)`。标定方法见
[docs/calibration.md](docs/calibration.md)。

## 定位顺序

`uiautomator` XML → 整页 OCR（psm 11 稀疏文字，再 psm 6 整块）→ band 裁片档（裁区域 +
autocontrast + ×3）→ pill 胶囊档（裁紧框，默认反色 + 硬阈值 120 + ×1/×2，靠颜色分开的控件
用 `PILL_MODE_<key>=color` 走"什么都不预处理、直接裁"）→ `COORD_*` 比例兜底（分数 0）。
第六档不是每个 key 都有：五颗要点的控件都配了——`subsidy` / `bag` / `light` / `take` / `dialog`；
只有 `exchange`（立即兑换）按口径永远不配，那一枪必须由她手动打。`bag` 和 `take` 这两颗
10-20 14:31 删过、15:15 又补回来，删与改各验了一遍，账目见 [docs/calibration.md](docs/calibration.md)。
psm 是 tesseract 的 page segmentation mode，页面分割模式，决定它把图当成一栏还是一堆散字。
band 档的 psm 默认全局 `7`，只有两把钥匙单独开了第二档 `7 6`：`browse`（10-18，浏览页那条低对比
横幅）和 `done`（10-26，券用掉之后顶部那行「已使用」）——都是按 key 加、不动全局值。
每一档是怎么量出来的、为什么不能改全局值，写在 [docs/locate-channels.md](docs/locate-channels.md)。

## 验收：改任何东西之前先跑沙箱

```sh
bash scripts/run-sandbox.sh                                   # 720x1280，约 5 分钟
SBX_SIZE=1440x2560 bash scripts/run-sandbox.sh                # 同一份标定数据换一块屏
bash scripts/negative-control.sh                              # 十条负对照，每条都应当挂
```

沙箱靠桩 `adb` 把点击事件记进文件，用例断言的是**点了什么、点几下、退出码、标记写没写、
app 关没关**，屏幕几何全部按 `SBX_SIZE` 折算。判据是 rc=0 且 `失败用例数: 0`。
换分辨率必须两遍都绿；细节和踩过的坑在 [docs/sandbox-testing.md](docs/sandbox-testing.md)。

改的是"值从哪儿来"这一类（外置配置、装载顺序）时，沙箱和负对照还不够——它们用的是桩图。
再加一道拿真证据跑的对照：`scripts/ab-replay.sh` 在存下来的 9 个场次上，让老字节和新字节各
跑一遍 `replay --ocr`，逐字比输出（判据是每个场次都 `IDENTICAL`，一个新字节带着配置、
另一个显式指一个不存在的配置文件走内建默认，两路都要过）。

## 凭据

这仓库是公开的，所以仓库里不许有任何真凭据。

- 真凭据有两个：ServerChan 的推送端点、离线归因那家的接口端点 + key。前者地址本身就带 send token，
  等于口令，所以它只写在主机的 `~/Desktop/pdd-push.url` 第一行（权限 600），脚本运行时读
  （[pdd.sh:291](pdd.sh#L291)）。读不到 = 没配推送：一条都不推，流程照跑。
- 轮换 token 只动那个文件，不改脚本、不进 git：
  `ssh deb-h61 'umask 077; printf "%s\n" "<新端点>" > ~/Desktop/pdd-push.url'`
- 环境变量 `PUSH_URL` 优先于文件，沙箱和临时覆盖走这条。
- 离线归因那条线（[tools/vlm-attribute.sh](tools/vlm-attribute.sh)，[docs/api-attribution.md](docs/api-attribution.md)）
  用同一个规矩管它的端点：只读主机的 `~/Desktop/pdd-vlm.url`（第 1 行 URL、第 2 行可选 key，权限 600），
  只报来源和长度，请求体里不写 URL 也不写 key。**这两个值不落任何文档、不落提交、也不落我这边的任何输出**。
  配好之前 `--send` 直接 `rc=78`、一个请求体都不建（那是实测过的）。注意 `githooks/patterns.sh` 那份表是
  5 类形态（ServerChan / 私钥 / GitHub PAT / Slack / AKIA），通用 API key 的形态挡不住 ——
  那个值进仓库只能靠人别贴（所以那份 `pdd-ocr.conf` 干脆不进仓库了，见下一条）。
- 外置那份 `pdd-ocr.conf` 11-01 起在 `.gitignore` 里，仓库不带它，所以就算谁不小心把端点值写进去，
  也没有"提交上去"这条路；但装载那一步的拦法一个字没撤：`VLM_API_URL` / `VLM_API_KEY` / `VLM_STUB`
  这三个键两边都专门拦（不是"不在名单里"那种泛泛的停，是单独一句"这是凭据或不走网络的后门"），
  写进去就 `rc=78`，装载那一步就停。主机那份的值是 `VLM_API_URL_FILE=~/Desktop/pdd-vlm.url` ——
  路径，不是值。
- 两道提交门禁，启用一次 `git config core.hooksPath githooks` 就都生效：
  `pre-commit` 扫暂存区，`pre-push` 扫这次真要传上去的每个 blob。命中凭据形态就拒绝；
  **扫不动也拒绝**（`git grep` 用法错、`cat-file` 挂了，都当失败处理，不当"没扫到"）。
  绕过是 `--no-verify`，只在确认那条命中是文档里的"形态描述"而不是真值时用。
- 沙箱里还有第三道独立的：被测的 `pdd.sh` 本体里有真凭据形态就直接 `exit 1`，
  绕过钩子也跑不起来（见 [docs/sandbox-testing.md](docs/sandbox-testing.md)）。
- 文件里另有无线 adb 地址（内网 IP）和主机路径，不含口令。SSH 免密用的公钥不在本仓库。
